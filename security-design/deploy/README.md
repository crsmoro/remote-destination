# Candidate deployment — blocked pending release gates

Do not deploy or route public traffic yet. The existing forward-auth applies globally; device exceptions, user authentication, egress and real Traefik mTLS remain unvalidated. Compose labels create a route if deployed. The backend has no UI authentication of its own. Do not disable global forward-auth. The relay is a trusted backend peer and has unrestricted outbound access if compromised; see ../egress.md. Docker host/admins and all private network members are trusted. The test below is not a test of the actual application topology.

On a trusted offline machine, run `sh provision.sh /absolute/path/to/new-private-directory`. Protect output and backups: keep `ca/` offline; securely transfer only `proxy/` to the nginx host and `traefik/` to Traefik, and deliver `device/device_key` separately. Do not copy secrets into this repository, images, labels, or logs. Leaf certificates expire in 90 days. Plan renewal/revocation and verify ownership and traversal permissions for the actual nginx, Traefik and Go container UIDs. Compose file secrets do not necessarily implement uid/gid remapping; the Go image runs as non-root. nginx reads its private key on startup; never grant world access. Treat the client certificate as authority to bypass forward-auth.

Set absolute host paths `WAZE_PROXY_PKI_DIR`, `DEVICE_KEY_HOST_FILE`, and `TRAEFIK_NETWORK`. `proxy/` must contain server.crt, server.key, client-ca.crt. Mount `traefik/` read-only as `/etc/waze-traefik` in Traefik, and arrange for its file provider to load `traefik-dynamic.yaml`. That requires a separately approved Traefik infrastructure change and reload; a Docker label alone cannot load the transport. Confirm the provider watches the intended path and that this transport overrides the global insecureSkipVerify. Never deploy the separate test CAs to production. Dedicated client CA authorization is CA-based, not subject pinning.
