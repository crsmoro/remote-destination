# Servidor de destino remoto

**Não publicar sem validar o proxy e a proteção Auth0 reais.** Este backend não valida sessões de usuário: `/` e `/api/` precisam estar exclusivamente atrás do middleware Auth0 confiável; `/device/` precisa de router dedicado, mais prioritário, sem Auth0 e com a chave do dispositivo verificada neste processo. A rede/porta do backend não pode ser acessível diretamente, nem por clientes não confiáveis. Não confiar em cabeçalhos de identidade de cliente. Esta configuração não cria routers, DNS, certificados ou redes e não comprova a segurança do Traefik.

**Consulta Google e seleção:** veja [google-geocoding-prototipo.md](../docs/google-geocoding-prototipo.md), inclusive limites e privacidade. O texto abaixo descreve também comportamento dos endpoints legados.

Configuração necessária: `DEVICE_KEY_FILE` aponta para arquivo privado contendo 32 bytes aleatórios codificados em base64url sem padding; forneça o arquivo através de um mecanismo de segredos com acesso de leitura pelo usuário não-root do container. `DATABASE_PATH` (padrão `/data/destinations.db`) deve estar em volume persistente gravável; `LISTEN_ADDR` padrão `:8080`. Não registrar a chave nem usá-la na URL. Rotação: substituir arquivo privado e reiniciar servidor; atualizar o cliente por canal seguro. Use TLS válido no proxy. O container roda sem root; monte volume persistente com permissões apropriadas, filesystem raiz read-only e `/tmp` temporário. Não publique a porta do backend.

Build: `go test -race ./...`, `CGO_ENABLED=0 go build ./cmd/server`, `docker build -t remote-destination .`. Requer Go 1.24.10; versão do driver fixada em go.mod/go.sum.

Links Google curtos são expandidos por HTTPS, com allowlist de hosts e caminhos, até cinco redirecionamentos, prazo limitado, DNS validado e IP fixado na conexão; proxy de ambiente não é usado. Existe um relay experimental opcional descrito em `../security-design/egress.md`. Falhas conservam o link original como pesquisa no Waze com aviso. Coordenadas de local em `/maps/place/` e uma consulta de coordenadas em `/maps/search/?api=1&query=latitude,longitude` podem ser extraídas; viewport não é tratado como destino. `venue_id` é preservado, mas sua navegação real precisa ser validada no Waze do carro.

No envio automático, quando o campo `city` é fornecido, um candidato sem cidade correspondente é recusado. A verificação lexical elimina alguns resultados incompatíveis, mas não prova identidade e não reconhece com confiabilidade uma cidade escrita no texto livre; não garante evitar destino errado. As requisições ainda não têm idempotência e não devem ser repetidas automaticamente. Essas limitações bloqueiam a ativação do envio automático seguro.

`failed` mantém o último estado e dados do destino para exibição, mas não o reapresenta no polling, evitando repetição; cancelar ou enviar outro destino o substitui. `claim` apenas verifica se o comando ainda está pendente: não reserva com exclusividade, e chamadas simultâneas podem ter sucesso. Após `claim`, cancelar/substituir pode chegar tarde demais; `intent_sent` não confirma navegação. Sem chave de idempotência para novas submissões, repetir uma requisição cuja resposta se perdeu pode gerar outro comando; a deduplicação no cliente não fornece exactly-once. Não houve verificação do Auth0, rede, navegador ou carro como parte deste servidor.

No envio automático de texto com duas ou mais palavras, o filtro rejeita candidatos sem nenhuma palavra de pelo menos três caracteres em comum com o rótulo ou cidade, ignorando acentos e admitindo prefixos de pelo menos quatro caracteres. Consultas de uma palavra ou sem palavras longas não são filtradas. É uma proteção limitada, não uma confirmação de identidade: palavras genéricas ou cidade coincidente podem deixar passar resultados errados, e abreviações podem não coincidir. A proximidade é apenas entre os candidatos retornados pelo provedor, não uma garantia global.

O SQLite usa `secure_delete=ON` para reduzir resíduos no banco principal, sem garantir apagamento de backups, snapshots, WAL/journal, mídia ou armazenamento subjacente. Proteja e expire essas cópias separadamente. ACK é idempotente enquanto o mesmo comando permanece atual; após substituição/cancelamento, uma repetição pode receber conflito. A entrega da resposta e a execução no dispositivo não são garantidas pelo backend.

## API M2M separada (opcional)

`AUTH0_AGENT_CLIENT_ID` habilita exclusivamente o cliente Auth0 M2M dedicado; não defina a variável para manter os endpoints desabilitados. Valor vazio ou inválido impede a inicialização. Configure `AUTH0_AGENT_ISSUER` com a URL HTTPS do emissor, terminada em `/`, e `AUTH0_AGENT_AUDIENCE` com a audience exata. Ambos são obrigatórios quando a API M2M está habilitada; não há valores padrão pessoais. Configure a API Auth0 com assinatura RS256 e autorize somente o aplicativo dedicado para `destination:write` e `status:read`. O servidor exige `azp` igual ao client ID configurado e `sub` igual a `<client ID>@clients`, além de assinatura, emissor, audience, expiração e escopo. Teste esses claims com um token real antes de publicar; não registre tokens nem credenciais.

`POST /agent/destinations` aceita apenas links de coordenadas validadas no JSON `{ "input": "..." }` e retorna a mesma resposta que o endpoint web de criação. `GET /agent/status` retorna o mesmo estado que a interface. Envie `Authorization: Bearer <access token>`; não existe operação de cancelamento na API M2M. Estes endpoints verificam o JWT no backend, não aceitam a chave do dispositivo, e o JWT M2M não concede acesso às rotas web nem do dispositivo.

No proxy, configure exceções separadas e exatas apenas para essas duas rotas e métodos, com maior prioridade que o router web, sem o forward-auth interativo; preserve o cabeçalho Authorization para o backend. Mantenha todas as demais rotas web atrás do forward-auth, o router do dispositivo separado e o backend inacessível diretamente. Verifique precedência, normalização de paths, métodos, cabeçalhos e ausência de bypass antes do deploy. O backend precisa acessar o JWKS do emissor configurado por TLS confiável; o cache de chaves dura no máximo cinco minutos e erros de JWKS fecham o acesso após expiração. Não é feita introspecção/revogação imediata dos tokens; use expiração curta e rotacione/remova as permissões quando necessário. Nenhum router ou serviço foi alterado por esta configuração.
